# Upgrade laravel-properties from 1.x to 2.0

Follow the steps in this order. Steps marked with **ASK** need a decision of the user.

## 1. Requirements

1. Check `composer.json`: PHP must be `^8.3` or higher and Laravel `^12.0` or `^13.0`. If not, stop and tell the user. Upgrading PHP or Laravel is a separate task.
2. Run `composer require tobymaxham/laravel-properties:^2.0 --with-all-dependencies`.

## 2. Find all usages

Search the app (not `vendor/`) for:

- `UseProperties` and `LaravelProperties\Traits`
- `$propertiesField`
- `getProperty(`, `setProperty(`, `emptyProperties(`
- `InvalidAttributeTypeException`, `InvalidObjectTypeException`
- casts of the properties column, e.g. `'properties' => 'array'`
- the column in migrations: `json('properties')` (or the custom column name)

List the models that use the trait.

## 3. Trait

Replace in every model:

```php
use TobyMaxham\LaravelProperties\Traits\UseProperties;
// ...
use UseProperties;
```

with:

```php
use TobyMaxham\LaravelProperties\HasProperties;
// ...
use HasProperties;
```

## 4. Default values of getProperty() — ASK

In 1.x `getProperty($key, $default)` ignored `$default` and returned `null` for missing properties. 2.0 returns `$default`.

1. Find every `getProperty()` call with a second argument.
2. For each call, check whether the following code relies on `null` (e.g. `=== null`, `is_null()`, `?? something else`, `if (! $value)` with a truthy default).
3. **ASK** the user for each call that relies on `null`: keep the default (new behavior) or remove the second argument (old behavior).
4. Calls whose code works with the default value need no change. They were buggy before and work now.

## 5. Column configuration

1. Replace `protected string $propertiesField = '...';` with `protected string $propertiesColumn = '...';`.
2. Remove a cast of the properties column from `$casts` / `casts()` if it is `array`, `json`, `object`, `collection`, `AsArrayObject`, `AsCollection` or an `encrypted:*` variant. The trait detects it, removing it keeps the code clean.
   - For `object`: 2.0 returns an `ArrayObject` instead of `stdClass`. Check code that uses `$model->properties->key`. `ArrayObject` supports this, but `instanceof stdClass` checks fail.
   - For `AsArrayObject` / `AsCollection` / encrypted casts: set the type explicitly so it is visible, e.g. `public const PropertiesCast PROPERTIES_CAST = PropertiesCast::Object;` (`use TobyMaxham\LaravelProperties\Enums\PropertiesCast;`).
   - Keep custom cast classes.

## 6. emptyProperties()

Replace `emptyProperties()` with `clearProperties()`. If the return value of `emptyProperties()` is used, replace it with:

```php
$old = $model->getStoredProperties();
$model->clearProperties();
```

## 7. New methods

Check every model with the trait for own methods with the same names as the new methods of the trait. The full list is in [UPGRADING.md](https://github.com/TobyMaxham/laravel-properties/blob/main/UPGRADING.md#new-methods).

**ASK** the user how to rename colliding methods of the app. Do not rename methods of the package.

## 8. Exceptions

- `InvalidObjectTypeException` is not thrown anymore. Remove `catch` blocks that only catch it, or catch `TobyMaxham\LaravelProperties\Exceptions\PropertiesException`.
- `InvalidAttributeTypeException` still exists. All exceptions extend `PropertiesException` (a `RuntimeException`).

## 9. Nullable column — ASK

If the properties column is not nullable (e.g. `$table->json('properties')` without `->nullable()`), creating a model without properties fails on MySQL.

**ASK** the user whether you should create a migration:

```php
Schema::table('users', function (Blueprint $table) {
    $table->json('properties')->nullable()->change();
});
```

Do not run the migration on other environments. Tell the user to run it.

## 10. Optional improvements — ASK

Only suggest these, do not apply them without the agreement of the user:

- Replace default values in code (`getProperty('theme') ?? 'light'`) with `propertyDefaults()`.
- Replace manual conversions (`(bool) $model->getProperty('newsletter')`, `Status::from($model->getProperty('status'))`) with `propertyCasts()`.
- Replace raw JSON queries (`where('properties->theme', ...)`) with the scopes (`whereProperty('theme', ...)`).

## 11. Tests

1. Run the test suite and static analysis.
2. Fix failures caused by the upgrade. Typical failures:
   - tests expecting `null` from `getProperty()` with a default (see step 4)
   - tests comparing the raw JSON (`[]` is now `{}`, unicode is not escaped anymore)
   - `setProperty()` returns the model instead of `null`
